    districts  205 rows   id = province*100 + n   e.g. 102
    communes  1683 rows   id = district*100 + n   e.g. 10201
    villages 14760 rows   id = commune*100 + n    e.g. 1020101
  Issues to fix on import:
  - Charset is utf8 (utf8mb3) per column -> convert to utf8mb4/utf8mb4_unicode_ci.

    in Settings (CRUD on geography), not hard-coded.
  - Keep the hierarchical code ids as-is (they mirror official NCDD-style codes).

1.3 member_db.sql (DO NOT import its people data)
  It is a different system (population / party members): tables communes,

    do not migrate. Keep the dump out of the git repo.
  - Useful ideas to reuse:
      * countries table (for "studied abroad" / foreign training) -> import.
      * jobs table (occupations: កសិករ, កម្មករ, គ្រូបង្រៀន, ...) -> reuse as the

        role_permissions(permission_key, action JSON ["1".."5"]) -> same
        concept, redesigned (section 6).
      * users.level (0=super admin, 1=national, 2=province ... ) -> becomes
        "data scope by unit" in our system.


--------------------------------------------------------------------------------
2. GOALS AND SCOPE
--------------------------------------------------------------------------------
  - One web app for the office to manage soldier records, incoming/outgoing
    official documents, appointment/transfer/promotion decisions, training,
    discipline, awards, retirement and separations, with reports.
  - Khmer-first UI (Khmer labels, Khmer numerals option, Khmer dates),
    English as secondary language.
  - Every change to a soldier's rank/position/unit/status goes through a
    recorded "decision" (history), never by silently editing the profile.
  - Role-based permissions: view / create / edit / delete / search / print /
    export per module, limited to the user's unit scope.
  - Runs on the office intranet; must work without internet (self-host fonts
    and all JS/CSS assets).

4. ARCHITECTURE
--------------------------------------------------------------------------------
  Browser (Vue 3 SPA) --HTTPS/JSON--> FastAPI --SQLAlchemy--> MySQL 8
                                         |--> /storage (photos, attachments)
                                         |--> PDF (WeasyPrint), Excel (openpyxl)

  Backend
    - FastAPI, Pydantic v2, SQLAlchemy 2.x (ORM), Alembic (migrations)
    - Driver: PyMySQL (or asyncmy if going async; recommend sync + threadpool
      for simplicity)
    - Auth: JWT access token (short) + refresh token; passwords with bcrypt
      (passlib/bcrypt)
    - PDF: WeasyPrint (HTML/CSS -> PDF; renders Khmer shaping correctly via
      Pango/HarfBuzz) with Jinja2 templates for A4 profile & decision letters
    - Excel export: openpyxl; Word (optional) python-docx
    - Tests: pytest + httpx TestClient; lint: ruff; format: black/ruff format

  Frontend
    - Vue 3 + Vite + TypeScript, Vue Router, Pinia
    - UI kit: Element Plus (tables, tree, forms, date pickers, upload)
    - vue-i18n (km default, en)
    - axios with token interceptor; route guards by permission
    - Charts: ECharts (vue-echarts) for dashboard
    - Fonts: Kantumruy Pro / Noto Sans Khmer (UI), Khmer OS Muol Light for
      official headings — bundled locally

  Database
    - MySQL 8, utf8mb4 / utf8mb4_unicode_ci, InnoDB, FK constraints on
    - Soft delete (deleted_at) on business tables; created_by/updated_by on all
    - Daily mysqldump backup + storage folder backup

  Deployment
    - Docker Compose: mysql, api (uvicorn/gunicorn), web (nginx serving the
      built SPA + reverse proxy /api)
    - Intranet server; HTTPS with internal certificate

5. DATABASE DESIGN (main tables)
--------------------------------------------------------------------------------
  Conventions: id BIGINT PK, created_at, updated_at, created_by, updated_by,
  deleted_at (where soft delete applies). Khmer name `name_kh`, `name_en`.

  5.1 Geography (imported)
    provinces(id, name_kh, name_en, type[រាជធានី/ខេត្ត], active)
    districts(id, province_id FK, name_kh, name_en, type[ស្រុក/ក្រុង/ខណ្ឌ], active)
    communes (id, district_id FK, name_kh, name_en, type[ឃុំ/សង្កាត់], active)
    villages (id, commune_id FK, name_kh, name_en, active)
    countries(id, name_kh, name_en)
    addresses are stored as (village_id + free text house/street); province/
    district/commune are derived from the village code — or stored
    denormalised for fast filtering.

  5.2 Organisation / master data
    units(id, parent_id FK self, level[1 ស្ថាប័នកងឯកភាព, 2 អង្គភាព,
          3 អង្គភាពរង, 4 អង្គភាពចំណុះផ្ទាល់], code, name_kh, name_en,
          sort_order, active)               -- tree; path/closure for subtree queries
    rank_classes(id, name_kh)               -- នាយទាហាន, នាយទាហានរង, ពលទាហាន
    ranks(id, rank_class_id, name_kh, name_en, short_kh, insignia_image,
          sort_order, min_years_to_next)    -- min_years drives promotion alerts
    positions(id, name_kh, name_en, level/grade, sort_order)
    specialties(id, name_kh, name_en)       -- ជំនាញឯកទេស
    document_types(id, name_kh, direction[in/out/both])
    education_levels, languages, blood_types, marital_statuses,
    soldier_statuses(id, name_kh)  -- e.g. កំពុងបម្រើការ, សិក្សា, ព្យួរ, និវត្តន៍, ចេញពីជួរ
    jobs (occupations, seeded from member_db.jobs)
    award_types, discipline_types, separation_reasons, course_types

  5.3 Soldiers (fields from 001)
    soldiers
      id, military_id (អត្តលេខ, UNIQUE), name_kh (គោត្តនាមនិងនាម),
      name_latin, gender, date_of_birth, national_id (UNIQUE NULL),
      birth_village_id + birth_place_text, current_village_id + address_text,
      photo_path, blood_type_id, phone,
      current_rank_id, rank_date (ថ្ងៃឡើងស័ក្តិ),
      current_position_id, position_date,
      current_unit_id, unit_transfer_date (ថ្ងៃផ្លាស់ប្ដូរកងឯកភាព),
      from_unit_text (មកពីស្ថាប័នកងឯកភាព),
      enlistment_date (ថ្ងៃចូលបម្រើទ័ព),
      status_id, education_level_id, specialty_id,
      combat_veteran (ឆ្លងប្រយុទ្ធ, bool + note),
      marital_status_id, spouse_name, spouse_job_id, children_count,
      father_name, mother_name, notes (បន្ថែមប្រវត្តិផ្សេងៗ)
    Computed (NOT stored; calculated in API/SQL views):
      age, service length (រយៈពេលបម្រើការងារ), time in current rank
      (រយៈពេលឡើងស័ក្តិ)
    Child tables (1-to-many):
      soldier_educations(level, specialty, institution, country_id,
                         domestic/abroad, start, end, duration)
                         -> covers រយៈពេលសិក្សា, សិក្សាក្នុងនិងក្រៅប្រទេស,
                            ក្រៅពីជំនាញឯកទេស
      soldier_languages(language_id, level)
      soldier_children(name, gender, dob)   (optional detail behind count)
      soldier_attachments(file_path, file_name, doc_type, uploaded_by)
      soldier_rank_history, soldier_position_history, soldier_unit_history
        (written by decisions in 5.5; current_* fields on soldiers are a cache
         of the latest history row)
    ប័ណ្ណសរសើរ / លិខិតសរសើរ come from the awards module (5.7) — do not keep
    them as free text on the profile.

  5.4 Official documents
    documents_incoming(id, incoming_no (លេខឯកសារចូល), subject (ខ្លឹមសារ),
      doc_date, received_date, document_type_id, from_unit (text or unit_id),
      status, remarks)
    documents_outgoing(id, outgoing_no (លេខ), subject, doc_date,
      document_type_id, unit_id, recipient_name, recipient_phone,
      status, remarks)
    document_files(id, document_kind[in/out], document_id, path, name, size)
    Numbering: configurable format e.g. "{seq}/{yy} ក.ត.ផ" with yearly reset;
    UNIQUE (number, year).

  5.5 Decisions (appointment / transfer / promotion)
    decisions(id, kind[appoint, transfer, promote, ...], decision_no,
      decision_date, effective_date, issued_by, outgoing_document_id NULL,
      attachment, status[draft, approved, cancelled], notes)
    decision_items(id, decision_id, soldier_id,
      old_rank_id, new_rank_id,
      old_position_id, new_position_id,
      old_unit_id, new_unit_id)
    One decision can cover many soldiers (a list in a ប្រកាស/ដីកា).
    On "approve": write history rows + update soldiers.current_* in one
    transaction. Cancelling reverts.

  5.6 Training
    training_courses(id, name, course_type[long/short], specialty_id,
      institution, country_id, start_date, end_date)
    training_participants(course_id, soldier_id, result, certificate_no,
      certificate_file)

  5.7 Discipline, awards
    discipline_records(id, soldier_id, discipline_type_id, reason,
      decision_no, decision_date, start_date, end_date, attachment)
    award_records(id, soldier_id, award_type_id [ប័ណ្ណសរសើរ, លិខិតសរសើរ,
      មេដាយ ...], decision_no, decision_date, reason, attachment)

  5.8 Retirement, category 2, separation, strength movement
    retirement_records(id, soldier_id, type[pension, category2],
      decision_no, decision_date, effective_date, pension_amount?, notes)
    separation_records(id, soldier_id, reason_id[discharge, resign, death,
      desertion, transfer out of ministry...], decision_no, date, notes)
    strength_movements(id, soldier_id, direction[in/out], reason, date,
      source_table, source_id)   -- feeds ការងារកើនថយ monthly report;
      written automatically by recruit / transfer / retire / separate actions.

  5.9 Security & audit
    users(id, username UNIQUE, password_hash, full_name, phone,
      soldier_id NULL, role_id, unit_scope_id NULL (NULL = all units),
      active, last_login_at)
    roles(id, name, description)
    permissions(id, module_key, action[view, create, update, delete,
      search, print, export, approve])
    role_permissions(role_id, permission_id)
    audit_logs(id, user_id, action, table_name, record_id, before JSON,
      after JSON, ip, created_at)

7. KEY FEATURES & BUSINESS RULES
--------------------------------------------------------------------------------
  Dashboard
    - Totals: soldiers by status, by rank class, by gender, by unit
    - Documents in/out this month; pending decisions
    - Alerts: soldiers due for promotion (time in rank >= ranks.min_years_to_next),
      nearing retirement age (configurable ages by rank class/gender),
      discipline periods ending, missing photo/ID data
  Soldier profile
    - Tabbed form: general, service (rank/position/unit), education &
      languages, family, awards/discipline (read-only from modules),
      attachments, history timeline
    - Photo upload with crop; Khmer + Latin name; duplicate checks on
      military_id and national_id
    - Advanced search: name (Khmer/Latin), military id, rank, unit subtree,
      position, status, age range, enlistment year, specialty, province of birth
    - Print A4 summary profile (ប្រវត្តិរូបសង្ខេប) with photo, official Khmer
      header (ព្រះរាជាណាចក្រកម្ពុជា / ជាតិ សាសនា ព្រះមហាក្សត្រ)
  Decisions
    - Create decision -> add soldiers -> preview old/new values -> approve
    - Validation: new rank must be higher than current for promotion; warn if
      time-in-rank is below minimum; unit/position must be active
    - Generate the decision letter / annex list as PDF
  Documents
    - Auto-number outgoing docs; attach PDF/scans; link to decisions
    - Search by number, date range, type, unit, keyword in subject
  Reports (PDF + Excel)
    - Strength report by unit and rank (តារាងកម្លាំង)
    - Monthly increase/decrease (កើនថយ) report
    - Promotions / appointments / transfers in a period
    - Training, discipline, awards, retirement, separation lists
    - Upcoming promotion & retirement lists
  Khmer specifics
    - Khmer numerals (០១២...) display option; Khmer month names; Buddhist
      calendar optional
    - Sorting Khmer names: utf8mb4_unicode_ci (verify sort order with users;
      consider utf8mb4_0900_ai_ci on MySQL 8)

14. IMPLEMENTATION NOTES (v1 built 2026-10-10)
--------------------------------------------------------------------------------
  Status: phases 0–7 are implemented (all menus and modules). Phase 8
  (user acceptance testing, real data import, deployment) is still to do.
  How to run: see README.md.

  Differences from the original plan:
  - Printing (A4 profile, decision annex, reports) uses print-styled pages in
    the browser (Ctrl+P / Save as PDF) instead of server-side WeasyPrint.
    Khmer text renders exactly as on screen and the server needs no extra
    libraries. Excel export is still done on the server (openpyxl).
  - Frontend is written in plain JavaScript, not TypeScript.
  - The small lookup lists (status, education level, language, blood type,
    marital status, occupation, award type, discipline type, separation
    reason) share one `lookups` table with a `category` column.
  - Rank/position/unit history is one table `soldier_histories`
    (kind = initial / appoint / transfer / promote / correction).
  - Editing rank/position/unit directly on the profile is allowed for data
    clean-up, but it is recorded as a "correction" history row.
  - Retirement and separation records change the soldier's status
    automatically and create an "out" strength movement. Deleting the record
    restores the previous status.
  - The A4 profile and print layouts are a first draft. Replace them with the
    office's official paper forms (open question 5).
